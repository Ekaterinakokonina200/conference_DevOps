# Разрешение merge conflict

## 1. Назначение

В рамках лабораторной работы был намеренно создан и вручную разрешён конфликт слияния Git.

Цель работы — продемонстрировать:

* параллельную работу с ветками;
* возникновение конфликта при изменении одного участка файла;
* поиск конфликтующих файлов;
* ручное разрешение конфликта;
* сохранение полезных изменений из обеих веток;
* фиксацию результата отдельным коммитом.

## 2. Использованные ветки

В демонстрации участвовали две ветки:

* `demo/conflict-source`;
* `demo/conflict-resolution`.

Обе ветки были созданы от одной версии ветки `main` до слияния первой ветки.

Это необходимо для того, чтобы обе ветки содержали независимые изменения одного участка файла.

## 3. Конфликтующий файл

Обе ветки изменяли файл:

```text
docs/contribution-rules.md
```

Изменения были внесены в раздел:

```text
## 6. Обязательные проверки
```

Исходный блок проверок имел следующий вид:

```powershell
ruff check .
python -m pytest
git diff --check
```

## 4. Изменение в первой ветке

В ветке:

```text
demo/conflict-source
```

в блок обязательных проверок была добавлена команда:

```powershell
alembic heads
```

Итоговый блок в первой ветке:

```powershell
ruff check .
python -m pytest
git diff --check
alembic heads
```

Изменение было зафиксировано коммитом:

```text
docs: add migration check before pull request
```

После проверки первая ветка была отправлена на GitHub, прошла review и была слита в `main`.

## 5. Изменение во второй ветке

В ветке:

```text
demo/conflict-resolution
```

в тот же блок была добавлена другая команда:

```powershell
alembic current
```

До получения изменений из `main` блок выглядел следующим образом:

```powershell
ruff check .
python -m pytest
git diff --check
alembic current
```

Изменение было зафиксировано коммитом:

```text
docs: add current migration check
```

Ветка была отправлена на GitHub до слияния первой ветки.

## 6. Причина возникновения конфликта

Обе ветки изменили один и тот же участок файла `docs/contribution-rules.md`, но добавили в него разные строки.

Первая ветка добавила:

```powershell
alembic heads
```

Вторая ветка добавила:

```powershell
alembic current
```

После слияния ветки `demo/conflict-source` в `main` во второй ветке была предпринята попытка получить новые изменения из `main`.

Поскольку Git не смог автоматически определить, какой вариант необходимо сохранить, возник конфликт слияния.

## 7. Получение изменений из main

Во второй ветке были выполнены команды:

```powershell
git fetch origin
git switch demo/conflict-resolution
git status
git merge origin/main
```

Команда:

```powershell
git fetch origin
```

получила актуальную информацию об удалённых ветках.

Команда:

```powershell
git merge origin/main
```

начала слияние актуального состояния удалённой ветки `main` с веткой `demo/conflict-resolution`.

## 8. Сообщение о конфликте

Во время слияния Git вывел сообщение следующего вида:

```text
CONFLICT (content): Merge conflict in docs/contribution-rules.md
Automatic merge failed; fix conflicts and then commit the result.
```

После этого команда:

```powershell
git status
```

показала файл `docs/contribution-rules.md` как конфликтующий.

## 9. Конфликтные маркеры

После возникновения конфликта в файле появились специальные маркеры Git:

```text
< < < < < < < HEAD
изменения текущей ветки
= = = = = = =
изменения из origin/main
> > > > > > > origin/main
```

В конфликтующем участке находились две команды:

```powershell
< < < < < < < HEAD
alembic current
= = = = = = =
alembic heads
> > > > > > > origin/main
```

Обозначения маркеров:

* `< < < < < < < HEAD` — начало изменений текущей ветки;
* `= = = = = = =` — разделитель двух вариантов;
* `> > > > > > > origin/main` — конец изменений, полученных из `origin/main`.

## 10. Ручное разрешение конфликта

Файл был открыт вручную:

```powershell
notepad docs\\contribution-rules.md
```

При разрешении конфликта были удалены строки:

```text
< < < < < < < HEAD
= = = = = = =
> > > > > > > origin/main
```

Обе полезные команды были сохранены:

```powershell
alembic current
alembic heads
```

Итоговый блок обязательных проверок стал выглядеть следующим образом:

```powershell
ruff check .
python -m pytest
git diff --check
alembic current
alembic heads
```

Таким образом, при разрешении конфликта не был выбран только один вариант. В итоговом файле были объединены полезные изменения обеих веток.

## 11. Проверка отсутствия конфликтных маркеров

После редактирования была выполнена команда:

```powershell
Select-String `
    -Path docs\\contribution-rules.md `
    -Pattern '< < < < < < <|= = = = = = =|> > > > > > >'
```

Команда не вывела результатов. Это подтвердило, что конфликтные маркеры были полностью удалены.

Также было проверено состояние репозитория:

```powershell
git status
```

## 12. Фиксация разрешённого конфликта

Исправленный файл был добавлен в индекс Git:

```powershell
git add docs/contribution-rules.md
```

Затем была выполнена проверка подготовленных изменений:

```powershell
git diff --cached --check
```

После этого результат разрешения конфликта был зафиксирован отдельным коммитом:

```powershell
git commit -m "chore: resolve contribution rules merge conflict"
```

Отдельный коммит позволяет явно показать в истории проекта момент ручного разрешения конфликта.

## 13. Документирование результата

Для описания выполненных действий был создан файл:

```text
docs/merge-conflict.md
```

Файл был добавлен в Git:

```powershell
git add docs/merge-conflict.md
```

Изменение было зафиксировано коммитом:

```powershell
git commit -m "docs: document merge conflict resolution"
```

## 14. Финальные проверки

После разрешения и документирования конфликта были выполнены следующие команды:

```powershell
ruff check .
python -m pytest
git diff --check
git status
```

Ожидаемые результаты:

* Ruff завершился сообщением `All checks passed!`;
* все автоматические тесты pytest получили статус `passed`;
* `git diff --check` не обнаружил ошибок пробелов;
* рабочая директория не содержала незакоммиченных изменений;
* конфликтующих файлов не осталось.

Дополнительно были проверены команды Alembic:

```powershell
alembic current
alembic heads
```

Текущая и последняя миграции должны совпадать.

## 15. Отправка ветки

После успешного выполнения проверок ветка была отправлена в удалённый репозиторий:

```powershell
git push
```

Для ветки `demo/conflict-resolution` был создан Pull Request в ветку `main`.

Pull Request прошёл проверку другого участника команды и был слит после получения `Approve`.

## 16. Результат

В рамках работы конфликт слияния был:

* намеренно создан в двух параллельных ветках;
* обнаружен Git при слиянии `origin/main`;
* найден с помощью команды `git status`;
* разрешён вручную;
* проверен на отсутствие конфликтных маркеров;
* зафиксирован отдельным коммитом;
* описан в документации проекта;
* проверен с помощью Ruff, pytest и Git.

В итоговой версии файла `docs/contribution-rules.md` сохранены изменения обеих веток:

```powershell
alembic current
alembic heads
```

Цель демонстрации merge conflict была достигнута.
